## 一、产品定位

### 1.1 一句话定义

**Lumina 是一个面向个人创作者和 KOL 的对话式 AI 营销智能助手平台**，通过自然语言对话帮助用户完成小红书/抖音等平台的内容营销工作。

### 1.2 产品形态

| 维度 | 定义 |
|------|------|
| **核心形态** | 对话式 AI 助手（类似 ChatGPT，但专注营销领域） |
| **辅助形态** | 工具型能力（内容生成器、账号诊断器、数据分析器） |
| **服务渠道** | 多平台：Web 应用 + 微信小程序/公众号 + API |
| **商业模式** | 付费订阅 SaaS |

### 1.2.1 接口统一化约束（v1.2 需求变更）

> **关键约束：对外服务层统一为单一入口 `POST /api/v1/services/system-chat/stream`，所有对话类能力必须通过该入口提供。**
>
> 原有独立服务流接口（`content-ranking`、`positioning`、`weekly-snapshot`）已下线，其能力以 **Skill / Agent** 形式挂载到 `system-chat` 中，通过用户自然语言关键词或意图识别唤起。
>
> **统一接口的协议、请求参数、响应格式、SSE 事件类型、错误码必须保持稳定。前端/第三方接入方只需对接一个端点。**

### 1.3 不是什么

> **明确边界，避免功能蔓延**

| 不是 | 说明 |
|------|------|
| ❌ 不是企业级营销中台 | 不面向品牌方的多账号矩阵管理 |
| ❌ 不是全自动 RPA 工具 | 不自动执行发布、刷量等操作 |
| ❌ 不是通用 AI 助手 | 不回答天气、笑话、编程等非营销问题 |
| ❌ 不是设计工具 | 不提供图片设计、视频剪辑功能 |
| ❌ 不是数据分析平台 | 不提供深度 BI、报表定制功能 |

### 1.3.1 接口统一化是边界问题，必须收敛

> 基于 v1.2 需求变更，对外服务层从多接口收敛为单一接口。

- ✅ **唯一对外服务流接口**：`POST /api/v1/services/system-chat/stream` 必须保持稳定
- ❌ **不再保留独立专项接口**：`POST /api/v1/services/content-ranking/stream`、`POST /api/v1/services/positioning/stream`、`POST /api/v1/services/weekly-snapshot/stream` 已下线
- ✅ **内容方向榜单（爆款榜单 TrendingRank）、定位矩阵（内容定位矩阵 ContentPositionMatrix）、每周决策快照（每周决策快报 WeeklyOpsBrief）** 以 Skill / Agent 形式挂载到 `system-chat`，通过关键词或意图唤起
- ❌ **不允许改变 SSE 事件格式**：`start`、`assistant_delta`、`export_link`、`compliance_report`、`done` 等事件类型和字段必须保持一致
- ❌ **不允许改变响应 JSON 结构**：`ok`、`layer`、`mode`、`intent`、`hub`、`reply` 等字段必须保留
- ❌ **不允许改变错误码**：现有错误返回格式必须保持一致
- ✅ **允许新增 Skill / Agent 能力**，但只能通过统一接口被唤起
- ✅ **允许内部重路由**：统一接口内部可路由到 MarketingOrchestra 或 Hermes，但返回给前端的 SSE 格式不变

### 1.4 与竞品的差异

| 竞品类型 | 竞品示例 | Lumina 差异 |
|----------|----------|-------------|
| 通用 AI 助手 | ChatGPT、Claude | **专注营销领域**，内置平台规则、方法论、案例 |
| 内容生成工具 |  Jasper、Copy.ai | **对话式交互**，不只是模板填充 |
| 数据分析工具 | 新榜、蝉妈妈 | **AI 驱动分析**，自然语言提问即可 |
| 营销课程/咨询 | 各类运营培训 | **实时辅助**，随问随答，不是一次性课程 |

## 二、目标用户

### 2.1 核心用户画像

**主要用户：个人创作者 / KOL / 小博主**

| 属性 | 描述 |
|------|------|
| **年龄** | 22-35 岁 |
| **平台** | 小红书、抖音、B站、视频号 |
| **粉丝量** | 1千 - 50万（成长型创作者） |
| **内容领域** | 美妆、穿搭、美食、健身、知识分享、生活方式 |
| **痛点** | 不知道写什么、写出来没人看、不懂平台规则、数据不好不会分析 |
| **付费意愿** | 中等（愿意为"涨粉"、"爆款"付费） |
| **技术能力** | 低（不熟悉专业工具，偏好自然语言交互） |

**次要用户：小品牌/个体商户的运营人员**

| 属性 | 描述 |
|------|------|
| **规模** | 1-3 人的小团队 |
| **需求** | 需要快速产出内容、监控竞品、优化投放 |
| **付费意愿** | 中高（内容产出效率直接关联收入） |

### 2.2 用户分层

| 层级 | 特征 | 需求 | 付费点 |
|------|------|------|--------|
| **新手** | 刚起步，粉丝<1万 | 起号指导、基础文案、平台规则 | 低门槛订阅 |
| **成长型** | 粉丝1-10万，有变现 | 选题优化、数据分析、爆款复制 | 标准订阅 |
| **成熟型** | 粉丝10万+，稳定变现 | 矩阵运营、深度诊断、竞品监控 | 高级订阅 |

### 2.3 用户的核心痛点（按优先级排序）

1. **不知道写什么**（选题困难）— 最高频
2. **写出来的内容没人看**（内容质量差）— 最痛
3. **不懂平台规则，经常违规**（合规风险）— 最焦虑
4. **数据不好，不知道哪里有问题**（分析能力弱）— 最困惑
5. **没时间研究竞品和热点**（信息获取难）— 最耗时

## 三、核心价值主张

### 3.1 价值主张陈述

> **"像有一个专业的营销顾问随时在身边，用对话的方式帮你解决所有内容营销问题。"**

### 3.2 核心能力（用户视角）

| 能力 | 用户描述 | 场景示例 |
|------|----------|----------|
| **账号诊断** | "帮我看看账号哪里有问题" | 用户发账号链接，AI 分析定位、内容质量、增长潜力 |
| **内容生成** | "帮我写个小红书文案" | 用户说主题和风格，AI 生成平台适配的文案 |
| **选题推荐** | "最近有什么热点可以蹭" | AI 推荐热点话题，结合用户定位给出选题 |
| **数据分析** | "为什么最近流量下降了" | 用户上传数据，AI 分析原因并给建议 |
| **合规检测** | "这篇会不会违规" | 用户发内容，AI 检测风险并提示修改 |
| **方法论指导** | "怎么写爆款标题" | AI 检索方法论库，给出具体技巧和案例 |

### 3.3 用户体验目标

| 体验维度 | 目标 | 衡量标准 |
|----------|------|----------|
| **自然** | 像和真人顾问对话 | 用户不需要学习命令或格式 |
| **连贯** | 记住之前的对话 | 多轮对话中不重复询问已知信息 |
| **专业** | 给出专业级建议 | 建议质量达到中级运营水平 |
| **快速** | 秒级响应 | 首字节 < 1秒，完整响应 < 10秒 |
| **可信** | 建议有据可依 | 引用方法论、案例、数据支撑 |

## 四、用户旅程与关键场景

### 4.1 典型用户旅程

```
发现 → 注册 → 首次体验 → 深度使用 → 付费 → 续费/推荐
```

#### 阶段 1：发现
- 渠道：朋友推荐、社交媒体、搜索
- 触点：小程序、Web 落地页

#### 阶段 2：注册
- 方式：微信一键登录 / 手机号注册
- 目标：降低门槛，快速进入体验

#### 阶段 3：首次体验（关键！）
- **场景 A**：用户说"帮我看看账号"
  - 期望：AI 问账号链接 → 分析 → 给出诊断报告
  - **痛点**：如果 AI 直接说"请提供链接"，体验差；如果 AI 不引导，用户不知道下一步
- **场景 B**：用户说"帮我写个文案"
  - 期望：AI 问主题/风格 → 生成 → 询问修改意见
  - **痛点**：如果 AI 直接生成默认内容，用户觉得不相关；如果 AI 问太多问题，用户觉得麻烦

#### 阶段 4：深度使用
- 用户开始定期使用，形成习惯
- 关键：AI 记住用户偏好、历史内容、账号数据

#### 阶段 5：付费
- 免费额度用完，或需要高级功能
- 关键：付费转化路径清晰，价值感知明确

#### 阶段 6：续费/推荐
- 用户觉得值，继续使用并推荐朋友
- 关键：持续提供价值，避免"用几次就腻了"

### 4.2 关键场景详细描述

#### 场景 1：账号诊断（新手用户）

```
用户：帮我看看小红书账号
AI：好的，请提供你的小红书主页链接，我帮你分析账号定位、内容质量和增长潜力。

用户：https://www.xiaohongshu.com/user/profile/xxx
AI：正在分析...
     
     【诊断报告】
     1. 定位清晰度：★★★☆☆
        - 问题：内容类型较杂，美妆和穿搭混合
        - 建议：聚焦一个领域，强化人设标签
     
     2. 内容质量：★★★★☆
        - 优点：图片质量高，排版整洁
        - 问题：标题缺乏钩子，点击率偏低
     
     3. 增长潜力：★★★☆☆
        - 粉丝增长趋势平稳，但缺乏爆款
        - 建议：尝试热点话题 + 实用干货结合
     
     需要我帮你优化定位方向，或者生成几篇符合你账号风格的文案吗？

用户：帮我优化定位
AI：基于你的内容分析，建议以下定位方向：
     ...
```

**关键需求**：
- AI 必须引导用户提供必要信息（链接）
- 诊断报告要具体、可操作，不是泛泛而谈
- 诊断后要有"下一步引导"（不能结束对话）

#### 场景 2：内容生成（成长型用户）

```
用户：帮我写个小红书文案，关于夏季防晒
AI：好的，夏季防晒是个热门话题。为了生成更贴合你需求的内容，想确认几个细节：
     1. 你的账号定位是什么？（美妆/护肤/生活方式）
     2. 风格偏好？（软植入/干货测评/种草清单）
     3. 目标人群？（学生党/上班族/宝妈）

用户：美妆账号，软植入风格，面向学生党
AI：收到，正在生成...
     
     【标题】学生党必看！这瓶防晒让我军训都没晒黑☀️
     
     【正文】
     姐妹们！军训14天我居然一点没晒黑...
     （内容省略）
     
     需要我调整风格，或者生成其他角度的版本吗？

用户：改得软一点，不要像广告
AI：（基于上一轮内容修改，不是重新生成）
     
     【修改版】
     姐妹们！军训14天我居然一点没晒黑...
     （更自然的表达，减少推销感）
     
     这个版本感觉如何？
```

**关键需求**：
- 信息不足时，AI 必须主动询问（不能猜测生成）
- 生成后要有"修稿"能力（基于之前内容迭代，不是重新生成）
- 对话要有连贯性（记住之前的主题和风格）

#### 场景 3：数据咨询（成熟用户）

```
用户：最近流量下降了，帮我看看
AI：好的，请提供最近 7 天的数据（阅读量、点赞、收藏、评论），我帮你分析。

用户：阅读量从 5000 降到 2000，点赞从 200 降到 80
AI：分析中...
     
     【流量下降分析】
     1. 内容层面：
        - 最近 3 篇标题缺乏数字和情绪词
        - 封面图风格不一致，影响点击率
     
     2. 发布时机：
        - 最近发布时间不规律（早中晚都有）
        - 建议固定在晚上 8-10 点发布
     
     3. 热点关联：
        - 最近内容没有蹭到热点话题
        - 建议结合"夏季护肤"、"618清单"等热点
     
     需要我帮你优化最近一篇内容的标题，或者推荐几个本周热点选题吗？
```

**关键需求**：
- AI 必须基于数据给出分析，不是泛泛而谈
- 分析要有"根因定位"，不是罗列可能原因
- 分析后要有"行动建议"，不是只指出问题

### 5.1.1 统一接口 Skill 能力（v1.2 新增）

基于 v1.2 接口统一化需求，以下三个专项能力以 Skill / Agent 形式挂载到统一接口 `POST /api/v1/services/system-chat/stream`，通过自然语言关键词唤起。

#### 爆款榜单（TrendingRank）

**定位**：多平台爆款内容聚合与智能排序引擎。

**用户故事**：
> 作为创作者，我想快速了解抖音/B站/小红书上最近什么内容爆了，以便找到选题方向。

**核心能力**：
- 跨平台（抖音、B站、小红书）爆款内容采集
- 关键词搜索 + 互动数据排序 + 平台榜单查看
- 支持按时间窗口（24h/7d/30d）、垂类分类筛选
- 关键词泛化：LLM 扩展同义词/近义词/行业黑话
- 多维度加权排序：`综合互动率 = (点赞×1 + 评论×3 + 收藏×2 + 转发×4) / 播放量`
- 去重与聚合：识别同一内容多平台分发

**输出**：结构化榜单（Markdown 表格）、爆款特征摘要、趋势词云、CSV/Excel 导出。

**触发词**：查爆款榜单、抖音热门、小红书爆款、B站 trending、全网热点、内容方向榜单、排一下方向。

#### 内容定位矩阵（ContentPositionMatrix）

**定位**：基于爆款分析的内容战略定位工具，识别内容的竞争位置与差异化机会。

**用户故事**：
> 作为创作者，我想知道我的内容在生态中处于什么位置，以及如何找到差异化定位。

**核心能力**：
- 输入单篇内容（URL/文本/截图），分析其在内容生态中的定位
- 构建"内容定位矩阵"：横轴专业度 × 纵轴娱乐度 × 颜色互动强度
- 识别内容空白区（Blue Ocean）与红海竞争区
- 输出差异化定位建议

**矩阵模型**：
```text
                    高娱乐度
                       │
    ┌──────────────────┼──────────────────┐
    │   娱乐消遣区      │     viral爆款区    │
低专业度 ──────────────┼────────────────── 高专业度
    │   日常分享区      │    知识干货区     │
    └──────────────────┼──────────────────┘
                    低娱乐度
```

**分析维度**：
- 标题语义分析（情绪词/数字/痛点/悬念）
- 正文结构分析（信息密度、段落长度、emoji）
- 视觉分析（封面类型：对比/数字/人物/清单/痛点）
- 专业度评分（1-10）、娱乐度评分（1-10）、互动强度

**输出**：定位坐标、矩阵可视化图（ASCII/PNG/SVG）、定位诊断报告、3 条差异化策略。

**触发词**：分析内容定位、内容矩阵、定位诊断、爆款定位分析、找差异化方向、定位矩阵。

#### 每周决策快报（WeeklyOpsBrief）

**定位**：基于本周作品互动数据的运营决策分析引擎。

**用户故事**：
> 作为创作者，我想每周自动生成运营复盘报告，明确下周该做什么。

**核心能力**：
- 自动采集本周发布作品的互动数据
- 多维度分析（内容类型/发布时间/互动结构/粉丝增长）
- 识别爆款因子与失败模式
- 输出下周运营策略建议（选题/发布/互动/投放）

**报告框架（3P 结构）**：
- **Progress（本周表现）**：核心指标仪表盘、内容类型表现矩阵、发布时间热力分析、TOP3 爆款拆解
- **Problems（问题识别）**：内容问题、发布时间问题、互动结构问题
- **Plans（下周策略）**：选题策略、发布策略、内容优化建议、投放建议

**核心指标**：
- 互动率 = `(点赞 + 评论×2 + 收藏×1.5 + 转发×3) / 曝光`
- 爆款率 = 互动率 > 5% 的内容占比
- 粉丝转化效率 = 新增粉丝 / 总曝光

**输出**：Markdown 报告、可视化图表、飞书多维表格推送（P2）。

**触发词**：生成本周快报、运营周报、决策报告、本周复盘、下周策略、每周决策快照、整理本周决策。

### 5.2 P0 功能详细需求

#### P0-1：对话记忆

**用户故事**：
> 作为用户，我希望 AI 记住之前的对话内容，这样我不需要重复说明我的账号信息和偏好。

**验收标准**：
- [ ] 同一对话中，AI 能引用之前提到的信息（如账号链接、定位方向）
- [ ] 跨对话中，AI 能记住用户的账号画像（内容类型、风格偏好）
- [ ] 用户说"刚才那个"、"之前说的"时，AI 能正确关联
- [ ] 记忆在服务重启后不丢失

**反例**（当前问题）：
- ❌ 用户第 1 轮说"我是美妆账号"，第 3 轮 AI 问"你是什么类型的账号？"
- ❌ 用户昨天诊断过账号，今天问"上次诊断的结果"，AI 说"我不记得了"

#### P0-2：渐进式内容生成

**用户故事**：
> 作为用户，我希望 AI 在生成内容前先了解我的需求，而不是直接生成不相关的内容。

**验收标准**：
- [ ] 用户说"帮我写文案"时，AI 先询问主题、风格、目标人群
- [ ] 用户说"改得软一点"时，AI 基于之前的内容修改，不是重新生成
- [ ] 用户说"再写一个"时，AI 保持相同主题和风格，换角度
- [ ] 信息不足时，AI 每次只问最关键的一个信息（不是一次性问所有）

**反例**（当前问题）：
- ❌ 用户说"帮我写文案"，AI 直接生成默认内容（不询问需求）
- ❌ 用户说"改得软一点"，AI 重新生成完全不同的内容
- ❌ 用户说"再写一个"，AI 问"写什么主题？"（忘记之前的主题）

#### P0-3：任务自主规划

**用户故事**：
> 作为用户，我希望 AI 能根据我的目标自动规划行动步骤，而不是我问一步做一步。

**验收标准**：
- [ ] 用户说"帮我运营账号"时，AI 提出"诊断→定位→选题→内容"的完整计划
- [ ] 每个步骤完成后，AI 自动引导到下一步（不是结束对话）
- [ ] 用户可以在任何步骤说"跳过"或"先做别的"
- [ ] AI 记住当前进行到哪一步，用户回来继续时不重复

**反例**（当前问题）：
- ❌ 用户说"帮我运营账号"，AI 只做诊断，然后结束
- ❌ 诊断完成后，用户需要重新说"帮我定位"才能进入下一步
- ❌ 用户中途离开，回来后 AI 说"你好，有什么可以帮你？"（忘记之前的任务）

### 5.3 功能边界

**必须做的（Must Have）**：
- 对话记忆（多轮 + 跨会话）
- 渐进式内容生成（先询问再生成）
- 任务自主规划（诊断→定位→选题→内容）
- 账号诊断（RPA + AI 分析）
- 基础内容生成（文案、标题、标签）

**应该做的（Should Have）**：
- 选题推荐（热点 + 定位匹配）
- 流量分析（数据解读 + 建议）
- 合规检测（风险识别 + 修改建议）
- 脚本生成（视频口播脚本）

**可以做的（Could Have）**：
- 方法论检索（知识库查询）
- 竞品监控（数据采集 + 对比分析）
- 多平台适配（一稿多改）

**不做的（Won't Have）**：
- 图片/视频生成（超出文本 AI 能力）
- 自动发布（平台政策风险）
- 刷量/涨粉服务（违规风险）
- 企业级矩阵管理（目标用户不是企业）

## 八、技术约束与选型原则

### 8.1 技术选型原则

> **业务逻辑和用户体验优先于技术栈选择**

| 原则 | 说明 |
|------|------|
| **用户价值优先** | 技术选型以"能否更快更好地满足用户需求"为标准 |
| **团队能力匹配** | 优先选择团队熟悉的技术，降低维护成本 |
| **渐进式演进** | 不追求一步到位，允许逐步优化架构 |
| **接口统一化** | **对外服务层统一为 `POST /api/v1/services/system-chat/stream`，专项能力通过 Skill / Agent 挂载；统一接口的协议、参数、响应、SSE 事件、错误码保持稳定** |
| **可回滚** | 任何改造都要保留回滚路径 |
| **可观测** | 关键指标必须有监控和告警 |

### 8.2 当前技术栈

| 层级 | 技术 | 用途 | 是否核心 |
|------|------|------|----------|
| **前端** | Web / 小程序 | 用户界面 | 是 |
| **API 层** | Python FastAPI | HTTP API、SSE 流式 | 是 |
| **编排层** | Python | 意图分类、Agent 调度 | 已决策退役（Phase 4 P2 移除） |
| **Skill 层** | Python | 业务逻辑（生成、诊断、分析、榜单、矩阵、快照） | 是 |
| **LLM 层** | DeepSeek / OpenAI | 模型调用 | 是 |
| **数据层** | PostgreSQL | 用户数据、用量统计 | 是 |
| **RPA 层** | Playwright | 浏览器自动化 | 是 |
| **底座** | Hermes Agent (Python) | 主执行引擎（Phase 4 起；原 orchestra 编排层退役中） | 是 |

#### 8.2.1 统一接口与 Skill 挂载原则

| 原则 | 说明 |
|------|------|
| **单一入口** | 对外只暴露 `POST /api/v1/services/system-chat/stream`，所有对话类能力统一入口 |
| **Skill 化挂载** | 爆款榜单（TrendingRank）、内容定位矩阵（ContentPositionMatrix）、每周决策快报（WeeklyOpsBrief）等专项能力以独立 Skill 注册到 Orchestra / Hermes（目标态：统一注册为 Hermes Tool，LLM 自主唤起） |
| **意图驱动** | 用户通过自然语言关键词（如"查爆款榜单"、"分析内容定位"、"生成本周快报"）触发对应 Skill（目标态：统一注册为 Hermes Tool，LLM 自主唤起） |
| **记忆统一** | 统一使用 `system-chat` 服务记忆，不再按原服务 ID 隔离，确保多轮对话连贯 |
| **渐进下线** | 原独立端点可在内部保留废弃兼容开关一个过渡期（建议 ≤ 2 周），最终必须下线 |

### 8.3 技术决策记录

#### 决策 1：OpenClaw 是否作为核心编排层？

**背景**：当前 OpenClaw 仅作为 HTTP 转发器，Python 层独立实现所有编排逻辑。

**选项 A**：深度集成 OpenClaw
- 优点：获得向量记忆、子代理、LLM 驱动编排等能力
- 缺点：工期长（11-16周），LLM 行为不确定，需要 Python ↔ TypeScript 桥接，会破坏接口稳定性
- **状态：已放弃**

**选项 B**：仅在 Python 架构上修复
- 优点：工期短（4-6周），风险低，团队熟悉，接口稳定
- 缺点：无法获得高级 Agent 能力，长期扩展性有限

**选项 C**：混合方案（已批准）
- 先 Python 修复（2-3周），快速解决用户问题
- 再逐步引入 Hermes Agent（4-6周）作为可选执行引擎
- 不引入 OpenClaw 深度集成，不做 A/B 测试
- 优点：快速见效 + 长期升级 + 接口 100% 稳定 + 风险可控

**当前状态**：**已决策，采用混合方案。执行文档见 `docs/LUMINA_HYBRID_RENOVATION_PLAN.md`**

> 2026-07-15 更新：定位由“Hermes 为辅”推进为“Hermes 唯一引擎”，见 `docs/specs/phase4_unified_planner_deprecation_spec.md`。

#### 决策 2：服务流接口是否统一收敛？

**背景**：当前对外提供 4 个独立服务流接口（`system-chat`、`content-ranking`、`positioning`、`weekly-snapshot`），前端需要维护多套调用逻辑，且与"对话式 AI 助手"的单一入口定位不符。

**选项 A**：保持 4 个独立接口
- 优点：前端改动小，接口边界清晰
- 缺点：能力入口分散，不符合对话式助手定位；每新增能力都需新增端点，扩展性差
- **状态：已放弃（v1.2 需求变更）**

**选项 B**：统一为单一接口，专项能力作为 Skill 挂载
- 优点：单一入口、对话体验自然、扩展能力强（新增 Skill 无需新增端点）、前端接入成本低
- 缺点：需要改造意图识别与 Skill 路由，需确保 system-chat SSE 格式兼容
- **状态：已批准，见 `docs/LUMINA_HYBRID_RENOVATION_PLAN.md` 阶段 3**

**决策结论**：
- 对外统一入口：`POST /api/v1/services/system-chat/stream`
- 爆款榜单（TrendingRank）、内容定位矩阵（ContentPositionMatrix）、每周决策快报（WeeklyOpsBrief）以独立 Skill / Agent 方式挂载
- 通过关键词或意图识别唤起，返回 SSE 格式与现有 `system-chat` 保持一致

#### 决策 3：记忆系统选型

**必须满足**：
- 持久化（服务重启不丢失）
- 支持多轮对话上下文
- 支持跨会话用户画像
- 查询延迟 < 200ms

**选项 A**：PostgreSQL + 应用层缓存
- 优点：团队熟悉，可控性强
- 缺点：不支持语义搜索

**选项 B**：OpenClaw MemoryIndexManager
- 优点：向量+FTS 混合搜索，语义检索
- 缺点：依赖 OpenClaw，调试复杂

**选项 C**：Redis + PostgreSQL 双写
- 优点：速度快，持久化
- 缺点：不支持语义搜索

**当前状态**：待决策
